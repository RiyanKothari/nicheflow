Build the Bookings module at route "/bookings". Use the authenticated layout.

HEADER:
- Page title using niche terminology (e.g. "Sessions" for dog trainer, "Bookings" for others)
- Right side: date range filter + "View: Month/Week/Day" toggle + "+ New Booking" accent button

CALENDAR VIEW (default):
- Full calendar using a custom-built or library calendar component
- Month view default — shows booking dots on days with appointments
- Week view — shows time slots in a grid, bookings appear as colored blocks
- Day view — detailed hourly timeline
- Color coding: teal = confirmed, amber = pending, gray = cancelled, green = completed
- Click any day/slot to quick-add a booking
- Drag and drop bookings to reschedule (update DB on drop)
- Today highlighted with accent color border

BOOKING LIST VIEW (toggle):
- Table with columns: Client, Service, Date, Time, Duration, Status, Actions
- Status badge with color
- Actions: View, Edit, Cancel, Mark Complete
- Sort by date, client, status
- Filter by status, service type, date range
- Search by client name
- Pagination — 20 per page

NEW BOOKING MODAL/FORM:
- Slide-in panel from right (not a popup — feels more native)
- Fields:
  · Client — searchable dropdown from client list, "+ Add new client" option
  · Service type — dropdown with niche-specific options from WorkspaceConfig
  · Date picker
  · Time picker — 30 minute intervals
  · Duration — 30min, 1hr, 1.5hr, 2hr, Custom
  · Notes textarea
  · Recurring toggle — None, Daily, Weekly, Monthly
  · Status — defaults to Pending
- "Save Booking" button + "Save & Send Confirmation" button

BOOKING DETAIL VIEW:
- Click any booking to open detail panel
- Shows all booking info
- Client profile mini-card with link to full profile
- Status change buttons — one click to change status
- "Generate Invoice" button — pre-fills invoice with booking details
- Edit and Delete buttons
- Notes section

REMINDERS:
- Each booking shows reminder status
- "Reminder sent" or "Reminder pending" badge
- AI auto-reminder logic: 24 hours before booking, send WhatsApp message (simulated for demo — show as notification)

BACKEND:
- GET /api/bookings — all bookings for user, filter by date range
- POST /api/bookings — create new booking
- PUT /api/bookings/:id — update booking
- DELETE /api/bookings/:id — soft delete
- PATCH /api/bookings/:id/status — update status only
- All endpoints protected, user-scoped
- Log every action to ActivityLog

Empty state: If no bookings, show friendly illustration + "No bookings yet. Add your first one →" CTA
